# 0.5.58 原生启动观察

2026-11-08。首次在 Windows 桌面直接启动非 headless 客户端并截图；不是完整原生验收。

## 已观察

- Godot 4.7.2 窗口正常启动，标题 `Billions Mech (DEBUG)`。
- 游戏视口渲染出：
  - 128×128 开发地图地形与边界
  - 初始主脑/基地几何
  - 我方单位与移动/待命指示
  - 城镇/矿点图标
- 左上角场景标题“四隘盆地 · 128开发图 / 128×128开发测试 / 战术视图”正常显示。
- 截图：[native-hud.png](screens/native-hud.png)。

## 启动窗口位置修复

- 观察：DPI 192 下窗口曾恢复到屏幕外 `x=-1087`。
- 修复：`_ready` 用 `DisplayServer.screen_get_usable_rect()` 把窗口位置约束到可用屏幕。
- 原生复核：不传 `--position` 启动，窗口 rect 为 `714,356,1207,662`，不再在屏幕外。
- 该修复只解决可达性，不代表 HUD/玩法完整验收。

## HUD 复核结论

- 该机器 DPI=192（200%）。游戏窗口逻辑 client 约 960×540，但物理截图需按 1920×1080 截取整个窗口。
- 之前用 960×540 截图只截到窗口左半，误判为 HUD 被裁切；按 1920×1080 物理尺寸截图后，完整 HUD 可见。
- 原生画面确认显示：
  - 顶部工具栏、重开/设置/操作
  - 左下小地图、防御计时、首波预告
  - 中部单位选择与指令说明
  - 右侧建造目录、五项资源、调度/电力/冷却
- 已用窗口消息发送 Space，原生 HUD 进入“已暂停 · 可规划”，计时停止；但焦点可能落在 HUD 暂停按钮上，不能据此证明游戏快捷键处理路径。
- 已发送 Q 进入算力节点建造模式，HUD 显示“左键下单、中键拖图、右键退出”。
- 已加入键盘建造兜底：建造模式下方向键移动光标、Enter下单。
- 但窗口消息注入的 Q/方向键始终没有得到可重复响应；可能只触发 HUD 焦点按钮而非游戏快捷键。
- 直接对建造菜单卡片和地图格发送 Win32 鼠标点击也没有改变 HUD/地图；当前环境的注入输入无法作为玩法验收手段。
- 暂不能据此验收建造。
- 已把 Q/W/E 与建造方向键/Enter 提前到 `_input`，并为合成事件增加 `physical_keycode → keycode` 兜底；仍未在原生注入中复现成功。
- 截图：[native-paused-build.png](screens/native-paused-build.png)。
- 未完成维修、驻防、合同、终波原生交互。
- 不能据此声称任何原生玩法验收完成。

## 结论

原生客户端可启动并完整渲染 1920×1080 HUD；此前“HUD 被裁切”的诊断是截图尺寸错误，不是布局缺陷。
