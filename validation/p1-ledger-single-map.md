# 五项资源账本与单一开发图

2026-11-08，0.5.26-dev。已开始P1核心代码迁移；本记录不表示P1玩法验收或版本A已经完成。

## 本批实现

- 删除`content/maps/first_outpost.tres`、`content/foundation.tres`、`content/training.tres`和临时开发主脑资源。唯一玩法入口为`content/development_128.tres`，使用“四隘盆地”128×128及统一`mainbrain.tres`（5×5）。移除训练场按钮、胜负页切场景按钮和`--training`分支；保留新地图诊断总览场景与内部场景重配命令，供既有检查使用。
- 资源使用Godot原生`Dictionary[StringName,int]`：`coins/metal_ore/fuel/alloy/crystals`。余额、造价、实付、退款、重建、采集、维修、墙线预算、工厂队列、感疫价值与HUD均迁移；实付和对外快照复制，避免后续修改资源定义改变旧订单的退款。
- 总算力、系统预留、净调度分别记账；建筑/单位/队列占用仍同账结算。冷却预留及供给以十分之一点整数保存，为后续20%减免留接口。数值不足限制新增需求，现有设施不因总量短缺自动关闭；纯供给恢复设施可在调度超载时按各自需求校验建造。
- 被毁基座保留土地/矿点绑定，释放运营额度；重建按定义造价50%逐项向下取整收费，并重新校验覆盖、电力、冷却和调度。重建施工取消退本次实付，后续拆除也基于本次实付。
- 工厂改为产品ID列表，单位改为按ID查找的目录；订单携带自身兵种、配方、容量和工期，出厂使用对应定义。HUD支持原生产品菜单；当前内容仍只配置卫兵。
- 建筑感染改用明确`infectable`标记，单位损失按自身定义估值；不再用建筑占容推断感染资格。未修改全局/局部行军场，也未把普通掉血加入供给重算触发条件。

实际复用为Godot Dictionary、Resource序列化、原生命令/结算和既有导航；项目代码仅新增资源数据转换与经营规则。外部库存/完整RTS框架的候选评估见[复用调研](../docs/reuse-research.md)。没有增加新测试脚本。

## 当前运行边界

仍运行6类建筑及卫兵。开局250币/50金属矿，主脑容量10/系统预留0/电力60/冷却0；节点仍提供6容量、消耗2电、产4币/分钟，当前冷却需求均为0。既有非零配方数值原样迁移，没有提前下调主脑供给或新增合金门槛。金属采矿站产金属矿，地图晶体改用正式`crystals`标记；燃料点仍在布局源预留，燃料/晶体矿站与合金加工尚未开放。

风能、太阳能、冷却塔、中继连通、节点4/1/3新平衡、600币新开局及侦察机属于下一批P2；加工配方、科技/升级执行接口随P3接入。31类建筑没有全部落地。旧“8节点提前首波”暂保留，需在新节点数值切换前重定，不能把本版当作新经济的平衡样本。
