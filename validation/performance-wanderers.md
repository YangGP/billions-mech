# 卡顿与游荡节奏调整

> 历史技术专题：文中“当前”指记录对应的版本。保留实现来源及当时证据，不继承为0.5.89功能/数值/人工验收。现行规则和待办见[开发计划](../docs/development-plan.md)，最近检查见[0.5.89记录](review-fixes-0.5.89.md)。


2026-11-07，0.5.18-dev。用户反馈明确为“建造、拆除或战斗时卡一下”和“开局游荡敌太早接近基地”。本轮优先处理重计算尖峰与准备窗口。

后续 0.5.19-dev 已再次放慢游荡敌的未交战与追击速度，当前值见文末；下文性能对照保留 0.5.18-dev 的测量配置。

## 修改

- 原先每次占用变化或定期 HP 漂移检查，都会在主线程重建普通行军场、穿墙行军场及原型机 A*，即使场上只有游荡敌。原路径一次实测约 **133.192ms**。现在只计算存活敌种需要的场，普通/穿墙场独立缓存，HP 签名采用真正参与成本的封顶值并排除目标主脑；A* 不随纯 HP 变化重建。
- 保留现有行军场算法，用原生 WorkerThreadPool 在独立地图/建筑状态副本上计算。每次最多一个任务；主线程只取已完成且地图版本一致的结果，过期结果丢弃并补算。沿用旧场期间仍检查实时地形/占用；首次场未就绪时对应行军单位短暂等待。原型机 A* 实例由工作线程独占构建，任务结束后交给主线程。重开/退出等待并回收任务，避免旧会话结果进入新会话。
- 网格分别记录地形、覆盖及占用格版本。玩家原生 A* 就地更新变更格；原生 RVO 保留边界，只释放/重建受影响行的障碍。基座通行、重建阻挡和占用释放都记录变更，新会话完整初始化。退出直接释放导航地图，避免先排队停用再释放造成无效地图命令。
- 视野不因普通建/拆重扫覆盖；源位置/数量变化时复制探索记忆字节数组，再合并可见格，省去每次遍历 128×128 网格恢复记忆。
- 游荡敌：标准地图禁刷半径 **20→28 格**，保持 1/100 候选格密度，候选 **4,363→3,203**，初始数量 **43→32**。未交战游荡/闻声移动 **1→0.35 格/s**，闲逛决策 **4→8s**、半径 **5→2 格**；交战追击仍为 **1 格/s**。噪声半径、边缘回填频率及正式波次参数沿用原值。
- `--perf` 新增模拟/表现/帧间隔峰值；后台场额外报告主线程提交耗时和工作线程耗时。

## 检查与性能证据

Godot 4.7.2 stable，GL Compatibility / RTX 4080 SUPER；未新增测试脚本。

| 检查 | 结果 |
|---|---|
| 原生资源导入、43 个 GDScript 语法检查 | 通过，无项目脚本解析/编译错误 |
| 既有视野检查 | 正式配置下 49 项、0 失败 |
| 正式标准开局 / 训练场 | 各 600 帧无头启动通过；标准开局确认 32 只、28 格禁刷 |
| 原生图形性能 | 标准开局全景按既有显示设置运行，开局加载后稳定接近 120 FPS；仅静止开局，不代表建造/战斗全程帧率 |
| 临时加速战斗 | 0s 静默、1s 预告、10s 波间隔、5s 放出窗口，预置训练建筑/四卫兵及两段墙，运行到 W3 原型机、W4、建筑被毁/感疫与主脑失败；退出 0，无项目脚本错误。临时改动仅为 Resource 数据，`finally` 恢复正式文件，未提交加速参数 |
| 主线程尖峰对照 | 仅加按需缓存的中间版，加速场景主线程模拟峰值 **132.330ms**；后台计算及局部更新完成后，同类场景为 **29.749ms**（不含首个初始化统计窗口）。场提交约 **0.04–0.14ms**，大额重建已转到工作线程 |

日志为 `.godot/perf-tune-*`，不提交缓存。加速场景的游荡散布未固定随机种子，以上用于定位尖峰，不是严格同种子基准；`--fixed-fps 30` 的无头日志不能作为实际渲染 FPS。正常配置复验与加速配置检查顺序执行，避免临时参数影响回归结果。受限环境仍报告系统根证书读取、编辑器全局设置保存错误。

## 边界

没有宣称彻底消除所有掉帧：加速重战斗仍出现约 30ms 主线程尖峰，启动首次导航/渲染初始化也另有成本；千级敌人、长墙批量操作及持续鼠标平移/缩放尚未验收。后台结果可能晚数帧，实战须复验破墙后的涌入、封墙后的改道、原型机穿墙，以及重开/切场景时任务回收。

28 格禁刷与慢速游荡增加开局准备空间，未设置保证安全时长；主动探图接敌后仍会正常追击。正式四波经济/难度与开局几分钟的压力需人工试玩。重新启动游戏后加载本轮代码与资源。

## 0.5.19-dev：游荡敌运动再调

用户试玩反馈：相比《亿万僵尸》，游荡敌移动仍然太快。上一轮仅将未交战移动降到 0.35 格/s，进入交战后仍以 1 格/s 追击，存在明显的速度切换。

本轮只调整 `content/enemies/wanderer.tres`，复用既有状态与地形减速逻辑：

| 状态（开阔地） | 0.5.18-dev | 0.5.19-dev |
|---|---|---|
| 闲逛 / 闻声趋近 | 0.35 格/s | 0.175 格/s |
| 接敌追击 | 1 格/s | 0.35 格/s |

配置为 `move_speed=0.35`、`wandering_speed_ratio=0.5`；崎岖地继续按原权重减速。禁刷 28 格、初始 32 只、闲逛决策 8s/半径 2 格沿用现值。目标是慢速蹒跚手感，没有将这些本作参数表述为原作实测数值。

本轮检查：Godot 4.7.2 资源导入、标准/训练场各 600 帧启动及既有 49 项视野回归；不新增测试脚本。实际接敌加速、闻声赶路与持续游荡的手感仍待人工复验。

## 0.5.20-dev：局部重寻路、刷新合并与分阶段计时

本轮针对“局部变化触发整图/全单位重算”的剩余主线程成本，不改变战斗数值与胜负规则。

### 修改

- `MechSimCore._sync_navigation` 不再对全部移动单位重新 A*：只有当前格不可走，或剩余路径段被新占用截断的单位才重算；远处建墙只更新原生 A* 的局部点数据。该判断使用现有 `mobile_segment_clear`，不改变路径合法性规则。
- 战斗结算合并刷新：敌人死亡不再触发经济与导航重算（敌人不占格、不占容量）；建筑连续受击的视野刷新延后到战斗阶段结束；建筑死亡后的导航刷新按整批命中只做一次；单位移动完成不再逐个更新视野；命令入口只对会改变占用/阶段/视野源的命令刷新导航与视野。
- 行军场改为**单张地形-only 共享场**：普通敌人与穿墙敌种（原型机）走同一张场，场只按地形权重积分到主脑。建筑、墙体及 HP 全部不参与全局路线；有墙时行进碰撞接敌，墙拆掉/无墙后沿同一张场继续。原型机只在步进/索敌时忽略装甲墙，追击仍保留专用原生 A* 墙占用豁免。
- 共享场在单局内静态，**建造、拆除、任何建筑 HP 变化都不再提交场重建**；原型机 A* 仍按非墙几何更新。低 HP 墙由附近敌人在索敌时局部选择：墙优先于其他建筑，墙之间先比 HP、再比距离，不改变全局路线。
- `--perf` 新增 `[perf:stages]`：按 `income / construction / economy / nav / production / vision_pre / units / enemies / nav_combat / vision_post / towers / step / tail` 统计平均与峰值，并保留最差 tick 的完整阶段拆分；同时输出 `nav_rebuild`、`nav_repath`、`vision` 次数。

### 检查与证据

Godot 4.7.2 stable，GL Compatibility；未新增测试脚本。

| 检查 | 结果 |
|---|---|
| 原生资源导入、标准开局 120 帧、训练场 120 帧 | 通过，无项目脚本解析/运行错误 |
| 临时加速训练场（1s 静默、200 预算、四波；仅改 Resource 后 `git checkout` 恢复） | 地形共享场与原型机 A* 均实际执行；场景内共享场只提交一次；无错误 |
| 标准开局 `--perf` | RVO 首次 `step` 约 **21.5ms**（原生初始化，仅首 tick）；稳定后最差 tick 低于 **1ms**，导航/视野不在峰值前列 |
| 加速训练场 `--perf` | 压力场景下 `enemies` 阶段峰值约 **40–125ms**；地形共享场首建约 **35ms**，原型机 A* 约 **40ms**，后续建造/HP 变化不再产生场提交；剩余主线程尖峰集中在敌人推进/接敌阶段 |
| 局部重寻路 | 仅在占用版本变化时检查剩余路径段；无受影响的路线不进入 A*。具体墙线/窄口绕行仍需人工操作复验 |

### 边界

以上加速训练场只用于定位阶段成本，不是正式节奏或同种子基准；200 预算、1 秒静默不代表标准开局压力，数字不能作为版本性能承诺。`--fixed-fps 30` 的无头日志不代表实际渲染帧率。

尚未验证：大量单位同时被截断路径时的重寻路收益、连续建墙时后台结果保留率、地形-only 场下“撞墙打墙 / 无墙直走”的实际墙线手感、共享场下原型机在墙线实战中的穿墙/追击行为，以及剩余 `enemies` 阶段内部的进一步拆分。移动观感仍受 30Hz 模拟位置直接绘制影响，本轮未接入插值。


## 0.5.22-dev：多区域与顺路目标

按用户确认，附近破口供未接敌单位优先进入，正在攻击其他墙体的单位保持目标；建筑只顺路破坏。单活动破口改为多区域缓存，局部积分读取实际阻挡并衔接全局边界值；HP 不参与。局部存储缩至区域尺寸，后台任务使用原生 WorkerThreadPool，主线程只提交副本并接收局部结构仍有效的结果。移动回调在 registry 的整批提交后只发一次，恢复批末视野刷新后既有视野回归为 49/0。

最终临时加速运行：60 首波预算、四波、20 段墙、1 厂/2 节点/4 卫兵；12 组区域/通行类型、43 次后台结果接收，地形全局场仅首建一次。局部提交 0.018–0.057ms（中位 0.035ms），后台积分 3.969–20.081ms；主线程最差 tick 仍为 42.641ms，残余热点在敌人推进/接敌，不能宣称所有卡顿已解决。与旧场景预算/随机种子不同，不作严格版本性能对比。资源导入、43 脚本、49 项视野及标准/训练场各 600 帧检查通过，详细规则、边界和人工待验见[局部场记录](assault-field.md)。
