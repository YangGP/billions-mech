# 代码架构

对应0.5.89-dev。Godot 4.7.2 / GDScript / 2D等距白模。当前进度只维护于[开发计划](development-plan.md)，技术来源和许可证见[复用调研](reuse-research.md)。目标规模与未接入方案不当作当前能力。

## 1. 模块复用边界

遵守[AGENT.md](../AGENT.md)：先评估成熟模块与原生能力，采用时保留来源和许可。现有 AStarGrid2D、NavigationServer2D/RVO、WorkerThreadPool、Resource、Control 和集中绘制继续复用；项目只做接口、数据及玩法规则适配，不因增加经营内容另建寻路或钱包。

## 2. 数据流

`表现/输入 → CommandQueue → SimCore权威校验与提交 → 状态信号/只读快照 → 表现`

实体为注册表中的纯数据状态，无逐单位逻辑节点。表现层集中绘制白模及拾取轮廓，不能反写实体。SimCore不依赖场景树或渲染节点；原生导航仍依赖Godot物理帧调度，因此无头运行也不能绕开引擎调度。

## 3. 核心原则

- 暂停只冻结模拟时间；命令仍校验、付款、预留和更新意图。
- 钱包、造价和实付是五项整数字典；冷却为十分之一点；收益/维修保留整数余数，对外快照复制。
- 共享Resource只保存不可变规则；实例保存进度、HP、产量、倍率、周期投入、订单及升级目标。
- 预览与提交共用规则，实际提交必须重查。命令失败不能留下半笔付款、占位、矿点/环境区预约。
- 伤害、回血及维修不重算地形全局场；结构/运营变化标记相关缓存，按战斗批次合并刷新。

## 4. 命令层

实际枚举见 `commands/sim_command.gd`，串行入口为 `MechCommandQueue` 及 `MechSimCore.validate_command/execute_command`。涵盖放置/墙线、取消/拆除/重建/维修、升级、生产/集结、单位指令、驻防/合同、区域配置及终波请求。

UI预览不授予免检权限，自动化也走普通命令。自动内部命令可以保留在途RVO批次，避免每次自动下单都截断全体移动；玩家指令按既有边界作废过时移动结果。不录制命令或实现回放系统。

## 5. 模拟模块与导航

| 实际模块 | 职责 |
| --- | --- |

| `grid_state.gd` / `grid_navigation.gd` | 地形/占用/覆盖版本、队伍通行、原生A*路径及直达校验 |

| `mineral_system.gd` / `alloy_processing.gd` / `environment_energy.gd` | 有限采集、炉内周期、按探索评分的环境电源及预约 |
| `construction_system.gd` / `building_state.gd` | 放置、并行施工、等级链、实付、基座和状态 |

供电覆盖从主脑根进行连通计算，独立 `coverage_revision`；断链必须处理远端连通组件，不能把“局部更新”误解为只修中继附近。覆盖变化不等于路径阻挡变化。环境电源只因相关探索/结构变化重评，光环写实例倍率；经营规则统一见[资源](resources.md)和[建造](building-economy.md)。

### 行军场与局部缓存

- **机潮行军（未接敌）= 单张地形流场**：波次目标为主脑；积分场只按 **地形权重** 计价（开阔 1 / 崎岖 2.0 / 障碍不可通行，实际地形权重取地图定义），建筑、墙体和 HP 不参与全局路线。墙/建筑是局部阻挡：场指向墙时，步进被挡即接敌啃墙；墙被拆掉或本来无墙时，行军单位沿同一张场继续朝主脑。普通与穿墙敌种**共用这张场**，穿墙敌种只在步进/索敌时对装甲墙放行。场在单局内静态，不因建造、拆除或 HP 变化重建，只有地图地形变化才需要重算；仅在有行军敌种时生成，首次场未就绪的行军单位短暂等待。复用原生 WorkerThreadPool 计算首次场；重开/退出回收任务。游荡敌的闻声/游荡继续走原生 A*。
  - **局部场 = 开口导流 + 顺路建筑目标**：在基地/玩家资产附近按需缓存 32×32 区域，中心间距 16 格。区域边界的可走格以全局积分值为初值，主脑周围可攻击位置也作为出口；局部按实际占用积分，未接敌单位选择有战略前进量且额外绕行成本不超过 8 的路线，附近破口可直接接到主脑方向。没有有效局部路线就沿全局方向撞墙攻击；已锁定的墙不会因其他地方破口而换目标。非墙、非主脑建筑周围可攻击格形成另一张多源场，只有路线成本 ≤3、落点不倒退、相对全局额外成本 ≤2 时才顺路接敌，不要求清空区域。源不可达则忽略；局部边界截断的路线允许回全局，不等待区域清空。
  - **区域缓存与失效**：同一区域/通行类型的敌人共用缓存，多个破口独立保留；敌人保持区域绑定，跨越内侧 2 格缓冲边界后再切换相邻重叠区。占用脏格只使受影响区域失效，额外检查一格边缘以覆盖区外建筑的区内攻击位；缓存的实际阻挡未变化则复用。局部构建复用 WorkerThreadPool，最多一个局部任务在途；任务只读独立网格/建筑副本和只读全局场，完成后仅校验本区结构及一格边缘，其他区域变化不丢弃结果。未接敌单位等待本区就绪，既有攻击照常结算；重开/退出回收任务。局部数组只分配区域大小，HP/维修不参与失效，地形全局场仍只首建一次。
  - **穿墙敌种（原型机）= 共享全局场 + 墙豁免局部场/A***：全局方向相同；局部区域按实际通行类型分别缓存，原型机忽略装甲墙，普通敌人把墙视为阻挡。追击继续复用专用原生 AStarGrid2D，目标落点、路径直达校验、跟随与碰撞均应用墙豁免；非墙建筑和地形仍阻挡。主动索敌均不远距离选择墙体，普通敌人实际撞墙后锁定攻击。
  - **机潮接敌 = sim 侧 A\***：进入攻击范围或被攻击时切出流场，做局部战术机动；脱离接敌（目标死亡、周围无敌）→ 回流场继续向主脑。
  - **玩家单位 = sim 侧 A\***：目标任意、数量少（容量约束保证），始终走 A\* 库。
  - **接敌判定必须空间分区**（网格桶，§9 规模的硬前提）：Marching/Engaged 切换的三条件见 vision-fog.md §5，判定半径为参数槽；实现上按桶内近邻查询，禁止全表扫描。
  - **对敌伤害单一入口**：单位与炮塔火力均以 hits 结果返回、由 SimCore 统一结算（`_damage_enemy`），原型机电磁庇护在此收口（每 hit 至多减免一次，庇护源同 tick 死亡即失效）。
- 状态机：`Marching(流场) ⇄ Engaged(A*)`，切换由现有敌军系统执行。

## 6. 表现与发布

`main.gd`收到状态信号只标脏，每渲染帧至多构造一次完整快照，输入、绘制、选择复用最近发布值；命令执行读取实时权威状态。原生移动批次提交后更新视野，暂停/重开作废旧回调。

静态地形采用SubViewport.UPDATE_ONCE纹理缓存，新会话/地图变化重绘，平移缩放只变换纹理；实体、覆盖、迷雾、选择和预览分别绘制。64×48等距投影统一正反变换及拾取。HUD使用Control锚点/Theme，肖像复用已有绘制器，仅在对象/阶段改变时更新。

玩家快照过滤视野外敌人和未知矿点；驻军不作地面实体，但保留其ID供编队存活性判断。战争迷雾在源变动时合成，灰色探索永久保留到重开。胜负冻结模拟和原生移动，镜头查看仍可用。

## 7. 内容与schema

图纸入口为 `content/building_definition.gd`、`unit_definition.gd`、`enemy_definition.gd`、`alloy_recipe.gd`、`foundation_settings.gd` 和 `map_definition.gd`。建筑等级通过 `upgrade_to` 连接不同定义ID，注册表实体ID不变；不能按旧提案假定所有等级共用building_id。

唯一正常配置为 `content/development_128.tres`，显式覆盖兼容默认值。建造目录JSON只负责分类/展示，不代替Resource或玩法接线。波次目前由FoundationSettings和WaveDirector表达，完整独立阶段构成仍待开发，不虚构已有WaveDef资源池。

## 8. 订单、回执和事件

生产系统终态回执区分取消退款、正常出厂和敌毁损失；区域付款记录与真实钱包同步，只有真实退款才回退原责任区域。维修在扣料前授权、付款后消费预算，重开清掉所有归属；合同和升级保存独立实付。

当前使用状态信号、结果字典及只读快照。完整EventBus、持久事件历史、求助管理和正式存档不是已有能力；不得将目标事件清单当作可调用API。

## 9. 设计规模与验证边界

目标同波在场机潮1–2k、玩家单位200–300、建筑约300–500，均未完成规模验收。空间桶、共享场、局部分区、视野外决策降频和缓存是现有基础；完整分区休眠/自动降速阀仍是后续方案。

`--perf`提供分阶段平均/峰值、最差tick及原生导航测量；压力入口保留建拆、探索和诊断敌人。必须同图、同配置、同种子比较，并分别记录模拟/渲染/导航，不能用无头FPS或旧地图缓存成绩证明当前大后期流畅。

## 10. 工程结构

运行目录为 `sim/`、`commands/`、`content/`、`presentation/`、`scenes/`、`vendor/`，资料为 `docs/` 和 `validation/`；`reference/`仅放忽略导入的本地参考源码，`archive/`仅留非运行原型。实际目录名以根README和仓库为准，不新增平行系统以匹配文档名。

## 11. 非目标

本轮不做联网、回放/回滚、正式存档、Mod编辑器或逐实体逻辑节点。区域有限自动化使用同一世界、钱包和队列；通用蓝图/策略编辑仍按开发计划补齐。当前脚本、启动、原生画面与人工验收边界查[验证索引](../validation/README.md)。
