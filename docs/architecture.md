# 代码架构（首切片骨架）

> 技术基线：**Godot 4.7、GDScript、2D 等距、模拟/表现分离**。本稿定义目标架构；实现进度与待明确规则见 [开发计划](development-plan.md)，选型结论见 [复用调研](reuse-research.md)，玩法来源见 [文档索引](README.md)。

## 1. 外部模块接入边界

输入/镜头/选择模块只能接表现层；战斗/队列/寻路适配后接 sim，先验证能否脱离原场景树。采用流程与候选清单统一维护在复用调研中。

## 2. 架构总览

```
┌─ 表现层 Presentation（Godot 场景树、输入、镜头与视图）────┐
│  渲染节点 / HUD / 输入捕获 / 放置模式客户端状态机           │
└──────────┬──────────────────────▲─────────────────────────┘
      命令（下发）           事件 + 状态查询（只读）
┌──────────▼──────────────────────┴─────────────────────────┐
│  命令层 CommandQueue（到达即执行，含暂停期）                │
├───────────────────────────────────────────────────────────┤
│  模拟核心 SimCore（固定 tick，可无头运行）                  │
│  ├ Grid 网格（地形/占用/供电覆盖/成本场/迷雾）               │
│  ├ 规则系统：账本/采集/容量/电力/建造/生产/威胁/战斗/视野   │
│  └ EventBus（模拟内部事件）                                │
├───────────────────────────────────────────────────────────┤
│  内容数据 Defs（Godot Resource：.tres）                     │
└───────────────────────────────────────────────────────────┘
```

**单向依赖**：表现层 → 命令层 → SimCore；SimCore 不 import 场景/节点/渲染类型，模拟可无头运行。

单位为注册表中的纯数据。当前白模表现层按快照集中绘制实体并处理拾取，不为每个实体创建常驻节点；逐实体影子节点仅为后续表现方案，尚未接入。

M4 玩家单位的局部避让直接使用 Godot NavigationServer2D / RVO，适配层只持有 RID，不创建单位场景节点。每个固定物理帧提交位置/期望速度，在同帧原生回调收齐后批量提交移动、刷新视图；暂停使待收结果失效并停用专属地图，重开/退出释放服务器资源。无头运行仍需引擎物理帧调度。来源与已知限制见 [复用调研 §6](reuse-research.md)。

## 3. 核心原则

1. **一切玩家行为皆命令**：建造、取消、拆除、维修开关、集结点、单位指令、生产下单——全部经短生命周期 CommandQueue 校验与提交，不持久化录制。
2. **暂停只冻结 tick**：命令仍即时校验与提交；施工、收入、波次、战斗和移动停止推进，表现层视觉动画可继续（operations.md §3.3）。
3. **数据驱动内容**：BuildingDef 字段与 building-economy.md §10 参数槽一一对应；敌种/波次同理。平衡调整不改代码。
4. **固定步长与整数资源**：收入/采集保留余数累积，暂停不推进；数值使用 values.md 的单位，不将每分钟产率误作每秒。

## 4. CommandQueue 命令层

- 命令结构：`{type, payload, seq}`；每条命令两个校验点：
  - **入队前 UI 快检**（廉价，驱动按钮灰显/放置预览着色）；
  - **执行时权威校验**（真实，拒绝则回执 UI 报错）。
- 两个校验调用**同一个纯函数**（`validate_placement`，见 §5 建造）——UI 与模拟永不各写一套规则。
- 首切片命令集：PlaceBuilding / CancelConstruction / Demolish / CancelDemolish / ToggleRepair / Rebuild（基座重建）/ RepairAll（一键修复）/ SetRally / QueueUnit / CancelProduction / IssueMove / IssueAttackMove / IssueAttack / TogglePause（元命令）。
- 单位类命令（IssueMove/Attack/AttackMove）入队后由 **sim 移动/战斗系统执行**，序号用于串行处理与回执；抵达队列直接复用 MIT RTSFormation 模块，项目适配落点、稳定偏移和朝向；局部避让直接使用原生 RVO，不引入命令录制。

## 5. Grid 与规则系统

- **空间数据**（同尺寸方格网）：地形层（三类 + 建造许可，map-terrain.md §3）/ 占用层（格→EntityId）/ **供电覆盖层**（bool + 来源标记）/ 成本场。视野为第五层，见 vision-fog.md §7；矿点另外保存类型、储量与采集绑定，不混作建筑占用。
- **当前局部更新**：网格分别记录地形版本、覆盖版本与各占用格的最后变更版本；原生 A* 就地更新变更格，RVO 保留地图边界并只重建受影响的合并行。基座转通行、重建恢复阻挡、释放占用均产生变更；新会话/地形变化才全量初始化。视野不会因普通占用变化重扫覆盖，实时视野源变化时直接复制探索记忆字节数组再合并可见格。性能与生命周期边界见[卡顿调整记录](../validation/performance-wanderers.md)。
- **供电覆盖传播（P2a）**：主脑为根；只有完工运行且自身格已被主脑/已连通中继覆盖的中继才加入 BFS，断开环不供电；覆盖 mask 只输出变更格，`coverage_revision` 与占用/导航 `revision` 分开，覆盖变化不重算地形行军场。中继/冷却塔被毁或拆除 → 覆盖/供冷级联失效，恢复/取消拆除/重建后恢复。
- **环境电源（P2b）**：风能/太阳能按已探索地形评分，实例保存运行时输出，不修改共享定义；同类采集区按 entity_id 预约，预览/下单/重建复用同一评分与冲突规则，0 输出拒绝。探索 revision 变化时才重算环境电源，不随单位逐帧全图扫描。
- **地图环境层（P2c）**：源 JSON 的风口/湖泊多边形经编译器同步为 `wind_cells`/`water_cells`；水域强制障碍地形（不可通行/不可建造、无库存），风口仅参与环境评分与程序化标记，不改变移动或全局行军场。
- **P2d 开局**：主脑提供净6调度/10电/4冷却/覆盖6，节点净3调度；初始2侦察机占调度2；正常配置不创建免费验证实体，诊断 fixture 显式开启。首波使用 `TIME_ONLY` 570s+30s，快照发布阶段/方向/倒计时。
- **P3a 冶炼**：燃料采集站绑定原生480燃料矿点；热能冶炼站使用不可变 `MechAlloyRecipe`，开工原子扣2燃料+可选1金属，15s完成产1合金并燃烧供30电。周期投入独立于建筑 `paid_cost`，主动拆除完成才退未完成投入。
- **P3b 升级**：等级 Resource 链 `upgrade_to` 只做原址替换；旧定义与服务在升级期间保持，完成时原子换定义并保留已损失HP。主脑 I→II 需运行科技I，科技I→II 需主脑II；普通升级可取消退差价，主脑不可取消。
- **P3c 维修**：4HP/s；每HP按当前有效新建配方的25%累计，分母`4*max_hp`，逐资源整数余数；原子扣料成功才回血，材料不足等待；余数保留并在升级换max_hp时分母换算。
- **放置校验管线**：building-economy.md §3.2 六步（地形→覆盖→重叠→电力→容量→资源），预览/命令快检/执行共用。最后一步检查币/矿石/金属/稀有并一并支付；采集站另检查矿点绑定，具体边界须在接入前补齐。
- **系统联动**：sim 协调事务内校验与提交，完成后通知视图；事件总线不替代事务边界。下表为目标职责拆分。

| 系统 | 职责 | 对应设计 |
|---|---|---|
| Ledger 账本 | 多资源库存、主脑/节点产币、支付/退款 | resources.md §3–§4、values.md |
| ExtractionSystem 采集 | 矿点绑定、被动采集、储量消耗与耗竭停产 | resources.md §4、map-terrain.md §4 |
| CapacitySystem 容量 | 提供/占用登记、超载判定、查询 | resources.md §5 |
| PowerSystem 电力 | 容量预留、覆盖传播、断供/级联/恢复 | resources.md §6 |
| ConstructionSystem 建造 | 校验管线、并行施工、血量爬升、退款、维修、拆除 | building-economy.md §3–§4 |
| ProductionSystem 生产 | 队列、付款占容、集结点 | building-economy.md §5 |
| WaveDirector 波次 | 首波触发、威胁预算、边缘出生、定性预告 | waves-enemies.md §2–§6 |
| Threat / Noise | 游荡敌回填、噪声聚拢、感疫生成与脉冲 | waves-enemies.md §4/§8.1 |
| CombatSystem 战斗 | 索敌、原型机庇护/跨墙/攻城、建筑目标与接敌 | waves-enemies.md §8、vision-fog.md §5 |
| VisionSystem 视野 | LOS、实时视野源、覆盖探索、三态迷雾 | vision-fog.md |

- 约束联动示例：中继被毁 → PowerLost → 覆盖内节点容量提供归零 → CapacitySystem 重算 → CapacityOverloaded → UI 警报。
- **寻路分工（按状态分轨）**：
  - **机潮行军（未接敌）= 单张地形流场**：波次目标为主脑；积分场只按 **地形权重** 计价（开阔 1 / 崎岖 2.0 / 障碍不可通行，数值稿 §11——Mindustry Pathfinder 口径），建筑、墙体和 HP 不参与全局路线。墙/建筑是局部阻挡：场指向墙时，步进被挡即接敌啃墙；墙被拆掉或本来无墙时，行军单位沿同一张场继续朝主脑。普通与穿墙敌种**共用这张场**，穿墙敌种只在步进/索敌时对装甲墙放行。场在单局内静态，不因建造、拆除或 HP 变化重建，只有地图地形变化才需要重算；仅在有行军敌种时生成，首次场未就绪的行军单位短暂等待。复用原生 WorkerThreadPool 计算首次场；重开/退出回收任务。游荡敌的闻声/游荡继续走原生 A*。
  - **局部场 = 开口导流 + 顺路建筑目标**：在基地/玩家资产附近按需缓存 32×32 区域，中心间距 16 格。区域边界的可走格以全局积分值为初值，主脑周围可攻击位置也作为出口；局部按实际占用积分，未接敌单位选择有战略前进量且额外绕行成本不超过 8 的路线，附近破口可直接接到主脑方向。没有有效局部路线就沿全局方向撞墙攻击；已锁定的墙不会因其他地方破口而换目标。非墙、非主脑建筑周围可攻击格形成另一张多源场，只有路线成本 ≤3、落点不倒退、相对全局额外成本 ≤2 时才顺路接敌，不要求清空区域。源不可达则忽略；局部边界截断的路线允许回全局，不等待区域清空。
  - **区域缓存与失效**：同一区域/通行类型的敌人共用缓存，多个破口独立保留；敌人保持区域绑定，跨越内侧 2 格缓冲边界后再切换相邻重叠区。占用脏格只使受影响区域失效，额外检查一格边缘以覆盖区外建筑的区内攻击位；缓存的实际阻挡未变化则复用。局部构建复用 WorkerThreadPool，最多一个局部任务在途；任务只读独立网格/建筑副本和只读全局场，完成后仅校验本区结构及一格边缘，其他区域变化不丢弃结果。未接敌单位等待本区就绪，既有攻击照常结算；重开/退出回收任务。局部数组只分配区域大小，HP/维修不参与失效，地形全局场仍只首建一次。
  - **穿墙敌种（原型机）= 共享全局场 + 墙豁免局部场/A***：全局方向相同；局部区域按实际通行类型分别缓存，原型机忽略装甲墙，普通敌人把墙视为阻挡。追击继续复用专用原生 AStarGrid2D，目标落点、路径直达校验、跟随与碰撞均应用墙豁免；非墙建筑和地形仍阻挡。主动索敌均不远距离选择墙体，普通敌人实际撞墙后锁定攻击。
  - **机潮接敌 = sim 侧 A\***：进入攻击范围或被攻击时切出流场，做局部战术机动；脱离接敌（目标死亡、周围无敌）→ 回流场继续向主脑。
  - **玩家单位 = sim 侧 A\***：目标任意、数量少（容量约束保证），始终走 A\* 库。
  - **接敌判定必须空间分区**（网格桶，§9 规模的硬前提）：Marching/Engaged 切换的三条件见 vision-fog.md §5，判定半径为参数槽；实现上按桶内近邻查询，禁止全表扫描。
  - **对敌伤害单一入口**：单位与炮塔火力均以 hits 结果返回、由 SimCore 统一结算（`_damage_enemy`），原型机电磁庇护在此收口（每 hit 至多减免一次，庇护源同 tick 死亡即失效）。
- 状态机：`Marching(流场) ⇄ Engaged(A*)`，切换判定归 CombatSystem。

## 6. 表现层对接（Godot 侧）

- **放置模式**（operations.md §3.2）是纯客户端状态机：幽灵预览调 `validate_placement` 着色，点击产出 PlaceBuilding 命令；拖拽连放在客户端聚合为批量命令。
- **HUD 读模型**：资源条/波次槽/警报直接查询 SimCore 只读接口；波次强度预告位吃 WaveDirector 的 payload（operations.md §8）。
- **现行读模型发布**：初始化后，`main.gd` 的状态信号只标脏，原生 `_process` 每渲染帧至多构造一次完整快照；绘制、选择、拾取与输入复用最近发布值。暂停/场景/频率采用廉价标量查询，命令执行始终读取实时权威状态；不在命令或单个原生移动回调中重复打包。
- **现行静态地形**：原生 SubViewport.UPDATE_ONCE 绘制地形至 ViewportTexture，由 Sprite2D 显示；相机平移/缩放只变换纹理。新会话/载入地图更新缓存，建筑占用变化仅更新覆盖与实体。缓存含边距、单边最大 4096 像素，节点随场景释放；动态实体、选择及预览独立绘制。
- **探索与实时可见（0.5.24）**：MechVisionSystem 对变化源先把半径内可玩格记为 EXPLORED，不检查 LOS；再沿用缓存的 LOS 足迹生成实时 VISIBLE 并集。探索记忆在源投射结束后原生复制，确保新灰格同次更新生效；源未变不重投射，不增加全图脚本循环。供电覆盖继续只提供探索；敌人快照/索敌仍只读实时 VISIBLE。
- **现行 HUD 与投影（0.5.23）**：MechIsoGeometry 统一 64×48 正反投影；实体绘制与拾取共用主脑外壳轮廓，通用建筑屋顶深度和墙连接取同一地格比例。相机用原生 Camera2D.offset 把焦点置于底部 280 像素指挥台及状态条上方，缩放锚点、可见矩形和边界约束共用可视区域。HUD 使用原生锚点/Theme/StyleBoxFlat；选中对象预览直接复用 MechFoundationView，在独立 World2D 的小 SubViewport 中按类型/施工阶段变更 UPDATE_ONCE，避免每帧重画肖像。全屏小地图保持在底部指挥台上方。
- **现行失败边界**：主脑移除时锁定会话失败，暂停既有时钟、作废并停用原生移动；本局玩法命令全部拒绝，只放行重开/载入场景。镜头与查看不暂停场景树。
- **现行胜利边界（首切片）**：波次导演收束（`total_waves` 波全部放完且无待出生）且场上无行军敌、无交战敌时锁定会话胜利，处理与失败完全镜像（时钟暂停、移动挂起、命令拒绝）；游荡敌游荡状态不阻止。完整单局终波胜利（玩家召唤，M9）沿用同一出口。
- **暂停视觉**：订阅 TogglePause 元命令，降饱和 + 常驻标识；模拟已被 tick 闸门冻结，表现层纯视觉动画可继续。
- **当前实体视图**：`foundation_view.gd` 按只读快照集中绘制单位和建筑，选择/拾取返回 EntityId，再经命令下发；表现层不写实体状态。逐实体影子节点、映射表与完整 EventBus 仍是后续方案，不作为当前接入状态。

目标事件：BuildingPlaced / ConstructionCompleted / BuildingDestroyed（转基座）/ BuildingRuined / ConstructionCancelled / Demolished（含清除基座）/ PowerLost / PowerRestored / CoverageChanged / CapacityOverloaded / CapacityRecovered / ResourceDepleted / WaveIncoming（定性强度 + 方向，不含精确数量/构成）/ WaveSpawned / WaveCleared / NoiseEmitted / InfectionTriggered / VisionChanged / UnitProduced / UnitDied / MainbrainDestroyed（= 失败）/ SliceVictory（切片终点）。名称为接口草案，不代表已全部实现。

## 9. 设计规模（非功能需求）

> 设计目标量级，是流场、模拟/表现分离和空间分区的设计依据，性能验证以此为基准；不是生成硬上限，尚未完成规模验证。

| 维度 | 目标 | 架构后果 |
|---|---|---|
| 机潮同波在场 | **1–2k**（留性能余量） | 行军必须流场；接敌判定/分离/索敌必须空间分区（网格桶），禁止 O(n²) |
| 玩家单位 | **200–300** | sim 侧 A\* 与避让须按目标数量验证；容量系统提供玩法约束 |
| 建筑总数 | **约 300–500**（墙段为主，估计值） | 覆盖/占用层必须脏标记增量更新；拖拽连放必须批量下单 |
| 同屏实体合计 | 数千（感疫连锁时可能尖峰超出） | 影子节点零逻辑纯视觉；选择/框选经映射表，不承担计算 |

**规模治理策略**：

- **分区休眠**：无威胁区块（无敌情、无玩家单位、无噪声源）的敌人进入低频模拟（数 tick 一跳），有事件唤醒。
- **迷雾外降档**：视野外敌人降低更新频率与寻路精度，与视野系统同批实现（vision-fog.md §7）。
- **降速阀**：负载超阈值时整体放慢 tick，表现为大场面慢动作。
- 感疫、波次、游荡敌回填不设数量闸，以运行时治理消化规模。

## 11. 非目标

- 不做联网/多人。
- 正式存档另排；没有回放需求，不加入命令录制、状态哈希或回滚。
- 不做区域层执行（新命令类型 + 新系统即可接入，不改核心）。
- 不做 Mod 工具链（数据驱动天然开放，编辑器不做）。
