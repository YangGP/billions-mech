## 1. 修正目标与边界

最终结构确定为：**二维逻辑地图＋平面三维地面＋实时三维建筑/单位模型＋正交Camera3D＋二维HUD**。地图中的位置、占地、距离、视野和战斗继续按格计算，模型高度属于表现。保留现有等距俯视方向和操作习惯，首轮固定镜头朝向，不新增自由旋转、地形高低差或飞行规则。

现有2D白模作为迁移基线，不能再被描述为最终技术目标。迁移先用Godot内置三维几何体制作可区分的模型占位，形成真正的三维场景；正式模型、骨骼动画和美术精修在接入规范确定后逐步替换，不作为修正架构的前置条件。

| 保留 | 迁移 |
| --- | --- |
| SimCore、命令队列、权威快照、实体ID和内容Resource | 主场景装配、地形/建筑/单位绘制、相机及表现坐标接口 |
| AStarGrid2D、NavigationServer2D/RVO、共享/局部行军场 | 鼠标到地图落点、模型点选、屏幕框选和可见屏幕判定 |
| 地图数据、占地/通行、钱包、生产/施工/拆除、敌人能力 | 建造/墙线/范围预览、选中标记、血条与能力提示 |
| 视野计算、探索记忆和视野外敌人过滤 | 三维地面与模型的迷雾着色、隐藏和拾取同步 |
| Control/CanvasLayer HUD、2D肖像、编队规则、暂停和命令语义 | 小地图镜头范围/定位接口及编辑器地图预览 |

模型不拥有血量、钱包、导航代理或战斗逻辑；不增加逐实体_process/物理更新，不改用三维导航或刚体来驱动玩法。三维可选拾取代理只负责返回实体ID，最终行为仍由原命令入口校验。

## 3. 关键技术约定

### 坐标与相机

- 一个逻辑格对应一个三维世界单位，逻辑`Vector2(x, y)`映射为`Vector3(x, height, y)`；格子中心加0.5，建筑origin仍表示占地左上格，朝向转换集中处理。
- 统一提供地图到三维、屏幕到地面、三维到屏幕、有效战场区域及镜头地面范围接口；所有建造、下令、框选和小地图经该接口调用，禁止各自复制换算公式。
- 直接复用[Camera3D](https://docs.godotengine.org/en/4.7/classes/class_camera3d.html)的正交投影、射线投射及屏幕投影API，平面求交复用Godot Plane。没有有效交点或落在地图外时返回明确的无效结果，不吸附到固定点。
- 固定斜向俯视，先保持两条网格轴的屏幕方向与当前一致。当前64×48菱形的轴线斜率为0.75；对等比例XZ平面、斜向45°相机，初始俯角约48.6°，最终按投影实测校准。屏幕网格线约36.9°不等于相机俯角。
- 平移速度和缩放按三维可见范围换算；镜头焦点仍落在扣除HUD后的战场中心。总览、地图边界和窗口尺寸变化都使用新的地面范围计算。

### 模型、地形与规模

- 地形按分块网格/共享材质构建，不能给128×128的每格创建独立常驻节点。真实地图轮廓外不铺可交互地面，水/岩体阻挡仍由原二维地图决定。
- 重复单位复用[MultiMeshInstance3D](https://docs.godotengine.org/en/stable/tutorials/3d/using_multi_mesh_instance.html)，按模型种类和空间分块管理；实体ID保存在快照/显示映射中，出生/死亡/升级/重开时更新，不能把实例下标当作实体ID。
- 共享Mesh/Material；可单独展示少量建筑或精英，但只由集中视图同步快照。MultiMesh整批裁剪的局限必须通过分块处理，不能依赖逐实例自动剔除。性能策略见[官方优化说明](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)。
- 定义模型原点、占地、朝向、可视包围盒、选择锚点、材质及替代模型的绑定规范；所有现有53个建筑定义、4类玩家单位和10个敌人形态都必须可显示、可辨认。31类建筑和22个升级形态不要求先做53套精美模型，但必须有明确等级和状态提示。
- 正式模型优先glTF/GLB，保留来源/许可证与导入设置；当前活动目录没有此类模型资源，第一轮使用引擎几何体占位。骨骼动画的批量表现需单独评估，不承诺MultiMesh直接复用逐实例AnimationPlayer。

### 选择与交互

- 点选用原生AABB粗筛和共享TriangleMesh的BVH求交，转换实例空间后按世界命中距离返回最近实体ID；不回退地面格建筑，不为每个单位挂玩法物理体。遮挡、模型空隙和真实输入仍须按人工清单复验。
- 框选继续按屏幕矩形与实体选择锚点判定，保留单位优先、Shift追加、Ctrl切换和编队。被己方建筑视觉遮住的友军仍可框选；视野外敌军不能因三维拾取被暴露。
- 保留双击单位的屏幕内同类与相邻链式扩选、建筑升级族同类选择；屏幕内判定改用新相机接口，不能再拿二维等距Rect2判定三维视野。
- HUD拥有先行输入拦截；框选端点仍裁剪到实际战场，鼠标可移入UI并松开完成选择，不触发UI操作。失焦/离窗取消手势；弹窗、设置和全屏小地图的输入优先级不变。
- 建造先鼠标跟随，方向键微调不带动镜头，鼠标移动恢复跟随；连续放置、墙线、非法格与暂停下单继续走原预览/提交校验。模型尺寸和旋转不改变逻辑占地。
- 小地图继续使用2D格子数据，点击先输出逻辑地图坐标再让相机聚焦；镜头范围用有效战场边缘射线与地面求交得到的多边形表示。肖像保留现有2D按需绘制，本轮不迁移。

### 迷雾与信息边界

- 沿用现有三态格子纹理和revision更新机制，适配为按世界XZ采样的地面/模型材质。黑雾、灰色探索与实时视野的规则仍由现有vision_system决定；模型高度不产生新的视线规则。
- 不能只在Y=0盖一张迷雾平面：高模型会露出。模型本体、特效、选中标记、血条、拾取代理及阴影必须同步遵守可见性；隐藏敌人立即退出批次及拾取集合，不从模拟全量状态另建敌人显示缓存。
- 普通完工连通建筑4格视野、拆除后的探索记忆、地形LOS、矿点发现规则保持；先验证跨视野边界的高模型和长足者穿墙画面，再推广到全部模型。
- 保持Compatibility可运行，优先采用通用空间材质、ImageTexture和网格；不依赖Forward+专属能力。若需要更换渲染器，先记录具体功能收益和同条件性能证据，再单独决定。

## 5. 验证与规模验收

遵守[AGENT.md](../AGENT.md)，不编写新测试脚本。复用Godot导入/解析、现有`validation/vision_checks.gd`、普通/战役入口及`--stress --perf`；人工检查与画面/性能记录另存于validation目录。

必验场景：主脑及1×1/2×2建筑落点、首次与连续放置、墙线、方向键/鼠标切换、取消、即时拆除/清基座和退款、建筑视野、模型重叠点选、单位优先框选、跨UI松开、双击升级族、编队、移动/攻击/驻防/出口、小地图/总览、窗口缩放、暂停/失焦/重开，以及长足者穿墙和五种精英提示。

性能基于已有2D历史基线与相同地图/配置/种子/硬件的3D结果比较；必要时从Git历史恢复2D版本，分别测模拟、渲染CPU/GPU、实例同步、draw call和内存/显存。1080p/60FPS作为初步画面目标，实际达标必须注明硬件；30Hz模拟预算与显示帧率分别检查，不能承诺尚未实测的机器表现。

现有目标规模仍为同波在场敌军1–2k、玩家200–300、建筑300–500；不得以地图总实体数代替可见实体数，也不得以空场或快速战败冻结后的帧率验收。先使用现有压力入口，若不能维持目标密度，调整既有诊断配置并记录范围，不另写测试脚本。3k+敌军及正式动画密度留作后续扩展。
