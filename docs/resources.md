# 资源与供给

对应 0.5.90-dev，2026-11-11已清理10类建筑及相关合同、经济加成和陷阱机制。B07零耗电风冷站尚待定值与实施，本稿的风能规则仅描述当前运行代码。当前数值查[数值表](values.md)，建筑生命周期查[建造经营](building-economy.md)，进度及验证查[开发计划](development-plan.md)。本稿取代旧“矿石/金属/稀有资源独立采集、冷却未来再做”的经济描述。

> 设计命名：原“燃料”改为**碳晶**，是一种有机-无机混合固体燃料；原“稀有晶体”改为**超导矿**。UI 显示名已切换；运行 Resource ID 仍为 `fuel` / `crystals`，数值表沿用这两个 ID。

## 1. 五项库存

| ID | 名称 | 来源 | 用途 |
| --- | --- | --- | --- |
| `coins` | 算力币 | 主脑、算力节点的被动收入 | 建造、升级、生产、维修 |
| `metal_ore` | 金属矿 | 有限金属矿点 | 前期材料、合金加工、中后期配方 |
| `fuel` | 碳晶 | 有限碳晶矿点 | 热能冶炼站的固体燃料投入 |
| `alloy` | 合金 | 热能冶炼站加工金属矿，兼供电 | 科技升级和中后期建设材料 |
| `crystals` | 超导矿 | 末期有限超导矿点 | 科技 III、高级形态及末期军备 |

按科技分层用料，不要求每项基础订单同时消耗全部材料。币、金属矿、合金、超导矿是建设配方的主要资源；碳晶是额外运营库存。库存全基地共享、无上限，无采集单位、运输、市场兑换、常驻币维护费或击杀奖励。

## 2. 采矿与工业

- 金属、碳晶、超导矿各用对应采集站；2×2 本体包含一个未耗竭矿点锚格，一站一矿，下单绑定。深层升级提高速度，不刷新或增加矿藏。
- 普通建筑不得覆盖未耗竭矿点。取消施工、移除建筑或清除基座释放绑定；完工建筑被毁留基座期间保留绑定。拆建不刷矿，整局重开才恢复初始储量。
- 采集以整数余数累计运行时间，断覆盖、施工、拆除和耗竭时停产；恢复不补发停机期间的收益。
- 基础热能冶炼每 15s 开工扣 2 碳晶，若有 1 金属矿则同时投入；本周期供电 30，结束产 1 合金。无金属仍燃烧发电，缺碳晶等待。
- 投入与周期进度属于建筑实例；暂停、断覆盖和拆除中保留，恢复不重扣。主动拆完退未完成周期投入，敌毁损失；升级先按旧配方结完当前周期，再切新定义。
- 首次实际合金产出开放科技 I；科技 II、主脑 III 和首座超导矿采掘站不需要预先持有超导矿。科技 III 再要求历史超导矿产出及相应配方。

## 3. 算力容量

节点继续同时承担产币和供容。容量分为总算力、系统预留和净调度：

`净调度供给 = 运行供容建筑的总算力 − 其系统预留`

基础节点总 4、系统 1、净调度 3。系统预留不再作为 `capacity_cost` 从净调度重复扣除。建筑、存活单位及生产队列共同占用调度；单位出厂只把队列占用转为单位占用。驻军仍占原调度。

超载禁止一般新增建造/生产，不关闭既有单位或设施；仅允许符合条件的零占容供给恢复设施新增，仍检查材料、电、冷却、地形和覆盖。建筑被毁成为基座后释放运营需求，重建须重新申请。

## 4. 电力与空间覆盖

**数值电量和空间连通分别结算。** 风冷提供冷却，太阳能/冶炼提供电量，中继提供覆盖；中继不发电，风冷/太阳能/冶炼不扩范围。

- 主脑是供电覆盖根；中继完工且接入已有连通范围后才继续扩覆盖。孤立中继环不能自供电，冗余连通可以保活。
- 建筑本体必须在覆盖内；覆盖可跨障碍，本体仍需合法可建地形。
- 下单预留需求，完工运行才供给。电量不足限制新增相关订单；已有连通设施不因总电量赤字连锁关闭。
- 覆盖断开则节点停产停供容、采集/供能/火力停运、工厂生产等待。墙保留物理防线；主脑自供能。重连自动恢复，不补发停机收益。
- 施工不因断覆盖倒退；完工后按当时覆盖决定是否运行。供给/覆盖只由实际结构及运营状态改变触发，普通掉血不触发全图行军场重建。

## 5. 无碳晶环境供给

风冷站 1×1，采集区 7×7；太阳能站 2×2，采集区 8×8，均为本体外扩 3 格。

只计已探索地格，灰区可计、未知黑区不计；排除本体、障碍及地图外地格。风口或崎岖格对风冷计 2，其他可用格计 1；太阳能只对开阔格计 1。基础输出分别为 **18 冷却**、**20 电力**，0 产量拒绝下单。强化同址翻倍，采集区不变，上限为 36 冷却/40 电力。风冷零耗电、不发电；太阳能只发电。

同类采集区排他、不同类可重叠，下单即预约。取消/移除/清基座释放，基座保留预约；重建重新检查当时探索与评分。产量存于实例，不修改共享 Resource。新探索只刷新相交电源，不随每次移动扫描全部电源或全图。

## 6. 冷却

冷却已接入，是共享供给额度，不是液体库存，也没有管道、水资源搬运或冷却液生产链。基础节点消耗电 2/冷却 2；基础冷却塔供冷 12、耗电 1。水冷站本体边缘须正交邻水，无水地图仍可使用普通冷却塔。

冷却按十分之一点整数结算，按节点图纸的基础需求占用。预览、施工、升级、重建和实际结算使用同一有效需求。冷却赤字限制新增需求，覆盖内已有节点不因此连锁停机。

## 7. 经营惩罚与付款边界

| 变化 | 结果 |
| --- | --- |
| 材料不足 | 新订单失败，不部分扣款 |
| 数值电力/冷却短缺 | 限制新增相关需求，既有服务保留 |
| 调度超载 | 禁止一般新增，放行合法零占容恢复设施 |
| 空间断覆盖 | 受影响建筑停止运营，重连恢复 |
| 战斗摧毁 | 损失订单/产能，依定义触发感染；无击杀回收收益 |

币和材料以同一整数钱包原子付款、按实付退款。区域 `budget_cap/committed/spent` 只是授权和责任归属，不从钱包另预扣一份资金；详细口径见[建造经营](building-economy.md#6-经营循环与区域预算)。

## 8. 非目标

不做食物库存、复合矿、旧独立铸造矿、资源市场、储仓上限、物流、昼夜/天气发电或常驻币维护。原始设计推导可从 Git 历史查询；当前建筑基准见[建筑 V2](building-roster-v2.md)，不再用旧账面例子描述当前运行状态。
