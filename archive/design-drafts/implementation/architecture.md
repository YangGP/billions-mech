# 代码架构（首切片骨架）

> 技术基线：**Godot 4.7 + RTS Advanced Lite（MIT，严格类型化 GDScript）作为基座**，代码 vendor 入库、锁定版本。范围 = 首切片骨架，区域层/战役/自动化只留接口。输入为五份设计文档（game-design-concept / resources / building-economy / operations / map-terrain，均位于 `../design/`），本稿不新增玩法规则，只定义它们如何落地。本目录 = 实现侧：本稿 + 未来 Godot 工程（§10 目录结构落在本目录下）。

## 1. 基座盘点（RTS Advanced Lite 已有 → 我们的用法）

| 框架已有 | 我们的用法 |
|---|---|
| 队伍（盟/敌/中立、队伍色） | 关系枚举移植 sim 侧；队伍色沿用框架表现：玩家 / 机潮 / 中立闲置 |
| 选择（框选/点选/shift/ctrl/编队） | 直接用（operations.md §4–§5 已按它设计）——作用于影子节点，经映射表解析为 EntityId |
| 指令（编队移动/攻击/停止）+ 阵型 | 指令执行与阵型槽位数学移植进 sim；输入/键位捕获沿用框架 |
| **8 向网格 A\* 寻路 + 障碍 + 分离避让** | A\* 与避让移植为 sim 侧寻路库（耦合度 M0 验证）；机潮行军走流场（分轨见 §5） |
| 单位战斗（血量/射程/冷却/追击） | 语义移植进 sim CombatSystem：加伤害修正表（精英抗炮塔）、建筑目标、接敌判定 |
| **生产队列（集结点、取消退款）** | 队列语义移植进 sim ProductionSystem：加"付款时占容"钩子 |
| 按队伍钱包经济 + 可占领收入点 | 钱包为 sim 侧账本（语义参考框架）；收入点**不启用**，收入源为算力节点被动产出 |
| 相机（俯视/平移/缩放/边界） | 直接用；全景缩放档调高上限 |
| 键位重绑定 + 冲突检查 | 直接用 |
| 114 个无头测试 | 作为 /tests 的模式扩展，模拟侧新系统照此补测试 |

**框架没有、全部要建的**：建筑放置/施工/拆除（我们最大的系统）、供电覆盖与级联、算力容量、波次导演、终局条件、暂停（完全暂停可操作）、迷雾/预警（后续）。固定 tick 循环按框架已有实现接入。

## 2. 架构总览

```
┌─ 表现层 Presentation（Godot 场景树 + 框架选择/相机/键位）──┐
│  渲染节点 / HUD / 输入捕获 / 放置模式客户端状态机           │
└──────────┬──────────────────────▲─────────────────────────┘
      命令（下发）           事件 + 状态查询（只读）
┌──────────▼──────────────────────┴─────────────────────────┐
│  命令层 CommandQueue（到达即执行，含暂停期）                │
├───────────────────────────────────────────────────────────┤
│  模拟核心 SimCore（固定 tick，可无头运行）                  │
│  ├ Grid 网格（地形/占用/供电覆盖/成本场）                    │
│  ├ 规则系统：账本 / 容量 / 电力 / 建造 / 生产 / 波次 / 战斗  │
│  └ EventBus（模拟内部事件）                                │
├───────────────────────────────────────────────────────────┤
│  内容数据 Defs（Godot Resource：.tres）                     │
├───────────────────────────────────────────────────────────┤
│  vendor/rts_advanced_lite（锁定版本：输入/相机/键位/选择沿用；│
│  单位逻辑源码作参考实现与测试对照）                          │
└───────────────────────────────────────────────────────────┘
```

**单向依赖**：表现层 → 命令层 → SimCore；SimCore 不 import 场景/节点/渲染类型。这条红线保证模拟可无头运行（数值批量验证、将来回放）。

**与框架的关系（立即彻底分离）**：单位是 **sim 实体**（注册表里的纯数据），场景树只放**影子节点**（渲染/选择用）。框架的角色随之分层——**输入捕获/相机/键位/选择直接沿用**（纯表现侧）；**单位逻辑（战斗、队列、阵型、A\*、避让）的语义移植进 sim**，框架源码作参考实现与测试对照；vendor 保持只读。这样 SimCore 单独可跑完整局（含单位战斗），表现层只是影子同步。

## 3. 核心原则

1. **一切玩家行为皆命令**：建造、取消、拆除、维修开关、集结点、单位指令、生产下单——全部经 CommandQueue 落账并记日志。
2. **命令到达即执行；暂停只冻结 tick**：暂停不拦截命令（钱与占用即时结算，operations.md §3.3），冻结的是 tick 推进——施工进度、产币、波次计时、战斗、单位移动。全分离后一切逻辑都在 sim，**暂停 = tick 闸门**即冻结全部；表现层纯视觉动画不受影响。
3. **数据驱动内容**：BuildingDef 字段与 building-economy.md §10 参数槽一一对应；敌种/波次同理。平衡调整不改代码。
4. **确定性基调**：固定 tick + 整数化资源（算力币整数；产币率 = 每 tick 整数增量 + 余数累积表——数值稿执行）。命令日志 = 回放源。
5. **框架为只读基座**：vendor 目录锁定 0.3.0；改动走"扩展优先于修改"（信号/继承/包装），确需改框架核心时在 CHANGE 提交说明里单列。框架很年轻（0.3.0），跟随上游升级必须走 diff 审查。

## 4. CommandQueue 命令层

- 命令结构：`{type, payload, seq}`；每条命令两个校验点：
  - **入队前 UI 快检**（廉价，驱动按钮灰显/放置预览着色）；
  - **执行时权威校验**（真实，拒绝则回执 UI 报错）。
- 两个校验调用**同一个纯函数**（`validate_placement`，见 §5 建造）——UI 与模拟永不各写一套规则。
- 首切片命令集：PlaceBuilding / CancelConstruction / Demolish / CancelDemolish / ToggleRepair / SetRally / QueueUnit / CancelProduction / IssueMove / IssueAttackMove / IssueAttack / TogglePause（元命令）。
- 单位类命令（IssueMove/Attack/AttackMove）入队后由 **sim 移动/战斗系统直接执行**（阵型槽位为 sim 侧数学，移植框架语义），seq 记日志——单位行为归 sim，命令层只管决策与记录。

## 5. Grid 与规则系统

- **四层数据**（同尺寸方格网）：地形层（三类 + 建造许可，map-terrain.md §3）/ 占用层（格→EntityId）/ **供电覆盖层**（bool + 来源标记，覆盖恢复溯源用）/ 成本场（崎岖地减速权重 + 阻挡）。
- **供电覆盖传播**：主脑/中继源 BFS；中继被毁 → 区域失效并级联下游（resources.md §6）；脏标记增量重算。
- **放置校验管线**：building-economy.md §3.2 六步（地形→覆盖→重叠→电力→容量→资金）实现为纯函数，放置预览、命令快检、命令执行三处共用。
- **系统与事件联动**（系统间不直接调用，全走总线）：

| 系统 | 职责 | 对应设计 | 来源 |
|---|---|---|---|
| Ledger 账本 | 钱包、节点产币入账、支付/退款 | resources.md §3 | 语义参考框架，sim 侧新建 |
| CapacitySystem 容量 | 提供/占用登记、超载判定、查询 | resources.md §5 | **新建** |
| PowerSystem 电力 | 容量预留、覆盖传播、断供/级联/恢复 | resources.md §6 | **新建** |
| ConstructionSystem 建造 | 校验管线、并行施工、血量爬升、退款、维修、拆除 | building-economy.md §3–§4 | **新建（最大件）** |
| ProductionSystem 生产 | 队列、付款占容、集结点 | building-economy.md §5 | 移植框架队列语义（集结点、取消退款）+ 占容钩子 |
| WaveDirector 波次 | 波次表、边缘出生带、强度预告 payload、威胁预算取样（规则见 waves-enemies.md §2–§4） | map-terrain.md §2 | **新建** |
| CombatSystem 战斗 | 索敌优先级、伤害修正表（原型机庇护减伤、攻城倍率，见 waves-enemies.md §8.2）、建筑目标、接敌判定 | building-economy.md §9.8 | 移植框架战斗语义 + 扩展 |
| WinLoseCondition | 主脑被毁=败；终波守住=胜（终波召唤命令后续版本） | game-design §3/§6 | **新建** |

- 约束联动示例：中继被毁 → PowerLost → 覆盖内节点容量提供归零 → CapacitySystem 重算 → CapacityOverloaded → UI 警报。
- **寻路分工（按状态分轨）**：
  - **机潮行军（未接敌）= 流场**：目标恒为主脑，成本场驱动（崎岖地减速编码为权重）；覆盖一次计算、全片共享；网格变化（建墙/墙塌/建筑被毁）→ 流场标脏重算，行军机潮下一 tick 自动改道。
  - **机潮接敌 = sim 侧 A\***：进入攻击范围或被攻击时切出流场，做局部战术机动；脱离接敌（目标死亡、周围无敌）→ 回流场继续向主脑。
  - **玩家单位 = sim 侧 A\***：目标任意、数量少（容量约束保证），始终走 A\* 库。
  - **接敌判定必须空间分区**（网格桶，§9 规模的硬前提）：Marching/Engaged 切换的三条件见 vision-fog.md §5，判定半径为参数槽；实现上按桶内近邻查询，禁止全表扫描。
- 状态机：`Marching(流场) ⇄ Engaged(A*)`，切换判定归 CombatSystem。

## 6. 表现层对接（Godot 侧）

- **放置模式**（operations.md §3.2）是纯客户端状态机：幽灵预览调 `validate_placement` 着色，点击产出 PlaceBuilding 命令；拖拽连放在客户端聚合为批量命令。
- **HUD 读模型**：资源条/波次槽/警报直接查询 SimCore 只读接口；波次强度预告位吃 WaveDirector 的 payload（operations.md §8）。
- **暂停视觉**：订阅 TogglePause 元命令，降饱和 + 常驻标识；模拟已被 tick 闸门冻结，表现层纯视觉动画可继续。
- **单位视图 = 纯影子节点**：实体注册表 ↔ 节点映射表；框架选择/框选作用于影子节点，经映射表解析为 EntityId 后下发命令；节点只读不写。
- 建筑视图同构（订阅 EventBus + 脏标记同步）。

## 9. 设计规模（非功能需求）

> 设计目标量级——是流场必做、立即分离、空间分区等架构决策的成立依据；波次稿数值不得超过，性能验证以此为基准。

| 维度 | 目标 | 架构后果 |
|---|---|---|
| 机潮同波在场 | **1–2k**（留性能余量） | 行军必须流场；接敌判定/分离/索敌必须空间分区（网格桶），禁止 O(n²) |
| 玩家单位 | **200–300** | sim 侧 A\* 无压力；容量系统为软上限的第二道闸 |
| 建筑总数 | **约 300–500**（墙段为主，估计值） | 覆盖/占用层必须脏标记增量更新；拖拽连放必须批量下单 |
| 同屏实体合计 | 数千（感疫连锁时可能尖峰超出） | 影子节点零逻辑纯视觉；选择/框选经映射表，不承担计算 |

**规模治理策略（不限制生成，运行时消化）**——目标量级是设计基准而非硬上限：

- **分区休眠**：无威胁区块（无敌情、无玩家单位、无噪声源）的敌人进入低频模拟（数 tick 一跳），有事件唤醒。
- **迷雾外降档**：玩家视野外的敌人降低更新频率与寻路精度（远处机潮粗粒度走流场即可）；迷雾/视野系统（vision-fog.md）因此成为性能与玩法双用途系统，实现优先级提前。
- **降速阀**：负载超阈值时整体放慢 tick 节拍（宁可慢、不许卡）；对玩家表现为"大场面自动慢动作"，与暂停可操作的精神一致（规划质量定胜负，不是手速）。
- **禁止**：为守数字上限而禁止生成（感疫、波次、游荡敌回填均不设数量闸）——规模的答案永远是治理，不是裁剪。

## 10. 目录结构（Godot 项目）

```
/vendor/rts_advanced_lite   # 框架锁定版（只读心态）
/sim                       # 纯逻辑：grid、power、capacity、construction、waves、ledger、events、defs
/commands                  # 命令定义 + 队列 + validate_placement
/content                   # .tres：buildings/ units/ enemies/ waves/ maps/
/presentation              # 放置模式、HUD、建筑视图
/tests                     # 无头模拟跑器 + 仿框架测试模式
```

## 11. 里程碑（每步可运行）

- **M0 框架摸底**：通读框架实体/指令/生产/经济模块；全分离下重点盘点**可移植件**（A\*、队列、阵型、战斗语义的耦合度与 lifting 成本）与**直接沿用件**（输入/相机/键位/选择），校准 §1 表格，锁定 vendor 版本。（先做）
- **M1 命令与暂停骨架**：CommandQueue + TogglePause + 实体注册表与影子节点绑定——验证"暂停冻结、命令即时、无头可跑"。
- **M2 网格与放置**：四层数据 + 校验管线 + 放置模式 UI——墙上花钱、能看到。
- **M3 经济活**：Ledger（节点产币）+ CapacitySystem——资源条跳动、超载禁建。
- **M4 建造闭环**：并行施工、血量爬升、取消/拆除退款、手动维修。
- **M5 机潮与终局**：WaveDirector 基础敌 + 边缘出生 + **流场行军（Marching/Engaged 状态机）** + 战斗扩展（建筑目标）+ 主脑被毁判负。
- **M6 单位**：组装厂生产（队列移植 + 付款占容）+ 集结点 + A 移。
- **M7 切片收尾**：HUD 全量 + 首个精英（伤害修正表）+ 强度预告 + SliceVictory。

## 12. 非目标

- 不做联网/多人（命令日志为将来留路）。
- 不做正式存档系统（命令日志 + 种子即回放，存档押后）。
- 不做区域层执行（新命令类型 + 新系统即可接入，不改核心）。
- 不做 Mod 工具链（数据驱动天然开放，编辑器不做）。
- 不做性能优化（首切片从简；流场已覆盖机潮行军，其余热点出现再议）。
