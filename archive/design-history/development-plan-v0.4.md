> **历史归档（2026-11-05）**：本计划未包含本轮新增设计；当前执行顺序见 [开发计划](../../docs/development-plan.md)。原稿中的系统链接指向当前专稿，不能视为当时设计的快照。以下保留旧计划内容。

> 版本：0.4。日期：2026-11-05。\
> 基线：按用户决定从空工程开始，旧原型的代码、场景、内容资源、默认数值和已完成里程碑不计入新项目。沿用已确认的玩法设计；外部已有方案继续优先复用。\
> 当前状态：M0 外部模块选型按功能继续补齐；M1、M2 已实现；M3 建造与经济闭环已实现并通过语法/导入/启动检查，点击交互与战斗受伤场景待人工验收；M4–M10 未开始。实施证据见 [重启记录](../../validation/rebuild-foundation.md)、[M2 记录](../../validation/m2-world-space.md) 与 [M3 记录](../../validation/m3-construction-economy.md)。

## 1. 开发目标与边界

按三个交付阶段推进：**首个可玩切片 → 三幕闭环 → 区域指挥**。先让建造、防守和少量调兵形成有趣循环，再扩展完整单局。

新工程沿用 Godot 4.7、GDScript、2D 等距表现，以及模拟/表现分离。Godot 内置能力和外部模块按功能比较，确认兼容性后锁定版本；不能复用先找其他已有方案，确认不合适后才实现本项目规则。旧原型实现不作迁移来源。

按用户后续指示，直接在本仓库根目录重建 `project.godot`、场景和内容入口，不另建子工程。旧脚本已删除；旧非代码资源归档在带 `.gdignore` 的 `archive/legacy-prototype/`。新入口为 `scenes/main.tscn`，仅引用 `sim/`、`commands/`、`presentation/` 和 `content/` 中的新实现。

## 2. 首个切片的交付范围

| 项目 | 范围 |
|---|---|
| 地图 | 一张手工灰盒图；固定主脑出生点；开阔/崎岖/障碍三类地形；单主口加一段开放侧翼 |
| 建筑 | 主脑、算力节点、装甲墙、哨戒炮塔、组装厂、雷达站 |
| 经济 | 算力币一个钱包；算力容量；主脑提供固定电力容量与固定覆盖；无采集单位 |
| 建造 | 下单付款并预留；并行施工；进度与血量独立；取消、拆除、维修；墙拖拽连放 |
| 单位 | 一种可生产的基础单位；移动、攻击、A 移、编队、集结点 |
| 敌人 | 普通机潮和首个精英；精英迫使玩家使用基础部队补位 |
| 波次 | 明确的准备时间、强度/方向预告、普通波和首个精英波；具体编排在 M0 定最小稿 |
| 情报 | 基础波次预告始终可见；雷达提供何种额外情报在 M0 明确；首版小地图显示主脑、己方实体与已获预警 |
| 终局 | 主脑被毁判负；预设波次全部出完且敌人清空判切片胜利；可重新开始 |
| 表现 | 优先灰盒、状态可读与基础反馈；正式美术不阻塞玩法验证 |

首切片不接入能源站、中继级联、常规建筑升级、主脑升级、区域委任或战役；不做完整迷雾系统。雷达的最小情报收益不能依赖尚未实现的完整迷雾。没有回放需求，不加入命令录制、状态哈希或回滚系统。

## 3. 必须沿用的规则

- **暂停可操作**：暂停冻结时间推进；建造、取消、生产下单和单位下令即时校验并更新状态，移动、施工和战斗恢复后推进。
- **统一命令入口**：同类命令的预览/按钮快检与执行校验使用同一规则；一条命令的扣款、预留与占格完整提交后才处理下一条。
- **容量超载**：既有建筑、单位和已付工程/队列继续运行；新增建造只放行零占容的容量恢复设施，仍须通过电力、覆盖和资金校验。墙与中继不享有该例外。
- **电力赤字**：供给损失后允许赤字，只禁新增下单，不因赤字冻结既有运行；能源站自身断供不提供容量。首切片无能源站，动态供给损失放到 M8 接入。
- **施工与受伤分开**：进度按时间推进，伤害扣当前血量；施工只增加新建成部分的血量，带伤完工不补满，当前血量归零可被毁。
- **建筑与流场分开**：机潮流场只计地形；实际移动仍受玩家建筑阻挡，遇到挡路建筑默认攻击。玩家单位和局部战术 A* 仍检查建筑阻挡。
- **收入来自基地**：算力节点被动产币；击杀无收益、残骸不回收。

详细规则以 [资源稿](../../docs/resources.md)、[建造经营稿](../../docs/building-economy.md)、[操作稿](../../docs/operations.md)、[地图稿](../../docs/map-terrain.md) 为准。

## 4. 首切片的开发顺序

每个里程碑都交付一个可运行版本；后一个里程碑建立在前一个的完整循环上，不先堆完所有系统再整合。M0 的局部验证只确认外部方案是否适配，不计为产品功能完成。

### M0：开发规格与外部模块验证

**目的：先确定“用什么做”和“第一段体验具体是什么”。**

- 按 [复用调研](../../docs/reuse-research.md) 核对候选；对选择/编队、2D 镜头、输入绑定、队列、A*、流场分别给出复用/适配/补充实现的结论，记录源地址、许可证、提交和依赖。
- 优先验证两个成本风险：外部选择/单位控制如何接入影子节点；外部寻路/战斗逻辑能否脱离场景树用于 sim。不能复用就比较其他已有方案，不先决定全部移植。
- 写首切片最小开发规格：建筑与基础单位数值、普通敌人与首个精英、波次表、雷达情报收益、开局资源与节奏目标。数值用于首轮验证，不视为最终平衡。
- 补齐实现必需的边界：在建初始可受击血量与舍入、友军占位时的阻挡/挤出、出厂位置受阻、目标失效后的行为、生产取消/工厂被毁时的退款与预留释放。规则写入对应设计稿，不由不同模块各自猜测。
- 确定新工程目录、渲染配置、模拟步长候选与经济结算周期，记录一台基准机器及帧率/模拟耗时目标。

**交付物**：模块选择表、首切片数值与波次最小稿、边界规则补充、新工程实施规格。

**验收**：关键外部依赖有明确接入路径；开局资金足以启动节点经济；基础单位在首个精英出现前有可行的生产窗口；不保留“某框架应该直接能用”的假设。

### M1：空工程与模拟骨架

**目的：建立新项目唯一的状态和时间入口。**

- 建立新工程、目录、主场景和启动入口；只引入 M0 选定的模块，不加载旧原型资源。
- 实体 ID 与注册表、固定步长时钟、暂停、统一命令入口、只读状态查询、影子节点绑定。
- 用最小可见实体贯通“命令 → sim 状态 → 视图刷新”；相机和面板状态由表现层保存。
- 规范系统执行顺序和事务提交边界；不引入持久化命令日志或通用网络框架。

**交付物**：可启动、可暂停、可下命令的最小新工程。

**验收**：模拟可无头启动；暂停时命令仍改变目标/订单状态，但游戏时间与时间驱动行为不推进；视图销毁或重建不会改写 sim 状态。

### M2：网格、地形与镜头

**目的：把同一份空间规则接到画面与输入。**

- 逻辑格、等距投影/反投影、地图边界、建筑占用、地形成本场；地图内容由数据定义。
- 三类地形、镜头平移/缩放/边界、光标格高亮、基础建筑占地预览。
- 制作首切片灰盒图，标明主脑点、主口、侧翼与初始可建腹地。
- 保持地形成本与建筑占用分离，为机潮流场和玩家 A* 提供不同读模型。

**交付物**：可浏览、拾取和预览占地的灰盒地图。

**验收**：缩放和平移后仍能准确选格；多格占地与视觉对齐；地图边缘、崎岖和障碍格给出正确建造许可；天然障碍与建筑阻挡数据可区分。

### M3：建造与经济闭环

**目的：玩家能亲手建基地，并承担时间和资金取舍。**

**实现状态（2026-11-05）**：四类建筑定义、整数账本、覆盖/预留、并行施工、取消/拆除/维修、连续放置和墙线已接入。按用户反馈恢复中键拖图，为左键框选腾出输入；墙线使用 Shift＋左键拖动。已通过语法和启动检查；未将未完成的人工交互验收计为通过，见 [M3 记录](../../validation/m3-construction-economy.md)。炮塔攻击在 M5 接入。

- 先接主脑、算力节点、装甲墙、哨戒炮塔四类定义；主脑为开局实体。
- 账本、节点收入、算力容量、固定电力容量/覆盖、六步放置校验；节点完工后才提供收入和容量。
- 并行施工、施工进度/血量独立、取消全额退款、完工后限时拆除与部分退款、取消拆除、手动维修。
- 建造栏、连续放置、墙拖拽连放、有效性预览、覆盖边界、资源/状态反馈；批量下单按顺序共享同一账本和预留状态。

**交付物**：可建造、经营、取消、拆改和修复的小基地。

**验收**：暂停中连续下单不会超支/超占用；取消和销毁不留下幽灵占格或重复退款；受伤不倒退施工，完工不清除伤害；节点损失后的超载只放行规定的容量恢复设施。

### M4：单位生产与指挥

**目的：让玩家在第一段战斗前具备可用的部队控制。**

- 接入组装厂和一种基础单位；独立队列、付款时占容、生产完成时预留转为实体占用、取消释放、集结点与出厂受阻处理。
- 点选、框选、混合选择、Ctrl+数字编队；单位移动、攻击指令与 A 移状态；玩家 A* 和基础避让。
- 通过可攻击的灰盒目标接通最小单位索敌/伤害，让 A 移可实际验证；M5 再扩展为机潮战斗。
- 单位指令、集结点与放置模式按操作稿处理输入优先级，不继承旧原型热键。

**交付物**：能生产、选中、编队并指挥基础部队的基地。

**验收**：排队即占容，出厂不会重复占容；单位损失/取消正确释放；移动不穿建筑与天然障碍；A 移能交战后继续前往目标；暂停时下令生效但单位不移动。

### M5：机潮与防守闭环

**目的：形成“建设 → 迎敌 → 损失 → 重建”的第一次完整循环。**

- 普通机潮、边缘出生带、波次计时、地形流场与接敌状态切换。
- 机潮实际移动检测建筑，阻挡时攻击；墙倒后继续沿流场前进；局部战术 A* 不绕过本应攻击的挡路墙。
- 炮塔、单位、机潮和建筑接入统一伤害/死亡流程；空间分区覆盖索敌、分离与接敌判定。
- 波次基本预告、主脑受击、失败、胜负后停止模拟、重新开局；此阶段先以普通波建立战斗闭环。
- 用可配置开发场景逐步增加在场数量，记录模拟/渲染/寻路耗时；检查最终设计上限的风险，不等正式美术和三幕内容做完再看性能。

**交付物**：可从建设玩到普通波胜负、失败后可重开的防守版本。

**验收**：完全封墙不使机潮失去行军方向；敌人不会穿建筑；破墙后恢复推进；暂停冻结波次、移动、伤害与施工；同局重开恢复干净的开局状态。

**规模依据**：最终目标仍为机潮 1–2k、玩家单位 200–300、建筑约 300–500。按 M0 基准机器与预算记录实际结果；首切片正常波次可以更小，规模检查不能把未达标写成“已支持”。

### M6：情报、操作与首个精英

**目的：把能运行的防守循环变成可理解、可指挥的首切片。**

- 接入雷达站及 M0 规定的情报收益；实现小地图、F1 跳主脑、QWERTY 建造槽、分类切页、状态面板与错误原因。
- 波次强度与方向信息呈现；基础预告无需雷达也可见，雷达增加信息而非使基本失败原因不可读。
- 接入首个精英及伤害修正，让基础单位承担炮塔之外的应对作用；通过预告与表现说明威胁，避免只在后台改倍率。
- 预设波次包含首个精英，全部出完且敌人清空后判切片胜利；完善受击/摧毁/断令等必要反馈。

**交付物**：六类建筑、基础部队、普通波和首个精英组成的完整切片。

**验收**：玩家能提前识别首个精英威胁，并有生产和调兵机会；小地图点击、建筑放置、单位命令和编队无输入冲突；胜利不会在仍有待出生敌人时提前触发。

### M7：切片体验迭代

**目的：决定当前玩法是否值得扩成完整三幕。**

- 调节点回本、建造时间、波间隔、墙承伤、维修成本、基础部队与精英关系；每轮只修改能解释问题的少量参数。
- 人工试玩记录五件事：是否主动规划布局；波间是在准备还是等待；首波是否紧张且可读；精英是否促成有效调兵；失败时能否指出自己的决策原因。
- 处理阻塞体验的寻路、反馈和操作问题；正式资产可逐步替换，但不靠增加建筑种类掩盖循环乏味。

**交付物**：可反复试玩的切片版本、问题与调整记录、下一阶段范围更新。

**验收**：能从开局连续玩到胜负，无阻塞问题；上述五项有实际观察记录。只有流程跑通但建设乏味、战斗只比数值时，继续迭代本切片，不立即扩三幕内容。

## 5. 首切片之后

| 里程碑 | 新增内容 | 主要验收 |
|---|---|---|
| M8：第二幕与电网 | 第一次主脑升级；能源站、中继覆盖及冗余/级联；赤字与断供分开；基础建筑升级、维修舱、陷阱、重装工厂 | 早升与晚升各有代价；能源站断供不供容量；赤字不误停其他建筑；恢复后自动续作；容量超载例外严格按规则执行 |
| M9：三幕与退守 | 第二次主脑升级、后期部队与威胁、至少两跳退守纵深、终波召唤与完整胜负 | 丢外线心疼但不直接判输；建设投入在后期仍有价值；拖延与升级压力可读；完整时长按试玩结果调整 |
| M10：区域指挥 | 在同一 sim 上加入授权、预算、重复事务处理、告警求助与玩家接管；按政策扩展电网 | 自动化不额外产资源/兵力；不代替玩家赢决定性战斗；求助可理解且可接管；完全手动仍可通关 |

M8 前补齐正式敌种/波次稿与升级威胁规则；M10 前补齐区域权限、预算与求助规则。战役、正式存档、美术音效生产和发行工作另排，不把当前首切片计划当作完整商业产品工期。

## 6. 执行与校验方式

- 每个里程碑保留可运行交付，记录完成项、已知问题与验收观察；旧原型的“已完成”不抵扣新计划工作。
- 每个新功能先检索已有方案；采用外部模块前核对许可证、版本、维护和依赖，记录为何适合本项目。
- 遵守仓库 AGENT.md：不编写测试脚本；代码变更做 GDScript 语法/导入检查，交互和玩法验收由运行版本人工检查并记录结果。
- 工期在 M0 明确实际复用率、适配成本和开发投入后按里程碑估算；当前按交付顺序排，不用未经验证的固定天数代替计划。

**当前推进到 M3：首轮规格见 [最小开发规格](slice-spec-v0.3.md)，实现与检查见 [M3 记录](../../validation/m3-construction-economy.md)。下一开发里程碑为 M4 单位生产与指挥，外部模块按对应功能继续选型。M3 点击试玩与受伤/维修验收仍须补齐。**
